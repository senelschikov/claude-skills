# comment-guard

Плагин Claude Code (мод на TypeScript-хуках `tool.call`), который держит комментарии и тела коммитов в рамках правил `skills/comment-style/comment-style.md`. Гайд и скилл `comment-style` идут в самом плагине. Лимиты: 5 строк на комментарий, 8 на заголовок нового файла, 25 % комментариев среди добавленных строк (от 8), 10 строк в теле коммита. Тронул плохой комментарий — поправь: изменение внутри блока длиннее лимита блокируется, а правка рядом с ним или в другом месте файла проходит. Блок до 10 строк проходит со второй попытки, более длинный только после сокращения.

## Что делает

- **Edit / Write / heredoc в Bash** — судит до записи. Первое превышение отклоняется, в отказ вставлена секция гайда. Повтор того же текста в той же сессии проходит с пометкой; превышение больше чем вдвое и правило доли отклоняются всегда.
- **`git commit`** внутри Bash — staged-диф по ханкам, `-a`, файлы из `git add` той же команды, тело коммита из `-m`/`--message`/heredoc.
- **После Bash** — файлы, которые команда изменила (`printf`, `sed -i`, `python -c`). Отказа после выполнения нет: находки приходят моделью как контекст «файл уже записан, сократите». Копии (тот же sha256, что у названного источника), файлы с незакоммиченными правками до команды, неназванные untracked-файлы и записи параллельных команд дают только мягкую пометку. Файлы вне репозитория проверяются, если их путь назван в команде: новый целиком, существующий по тому, что команда добавила к прежнему содержимому.
- **Старт сессии** — короткая форма из `skills/comment-style/SKILL.md` плагина и путь к полному гайду, и после компакта тоже.
- **Windows** — работает и на macOS/Linux, и на Windows. Платформа определяется по cwd сессии (буква диска — Windows); только тогда пути приводятся к виду `C:/x`, в том числе `C:\x` и Git Bash `/c/x`, и сравниваются без учёта регистра. Инструмент PowerShell судится как Bash: here-string `@'…'@` в `Set-Content`/`Add-Content`/`Out-File` как heredoc, `git commit -m @'…'@` как тело коммита, `Set-Location` и `$env:VAR` в путях. CRLF после `core.autocrlf` не мешает ни гайду, ни сравнению с `git show` и индексом.
- **Безопасность** — не читает `.env*`, файлы без кодового расширения, файлы больше 1 MiB, `/tmp` и временные каталоги Windows (`%LOCALAPPDATA%\Temp`, `C:\Windows\Temp`), прозу (md/txt/rst, docs/, README/CHANGELOG). В `$.state` и `$.store` только хеши и счётчики.

## Установка, включение и выключение

- Установка: `claude plugin marketplace add git@gitlab.advsys.work:devops/claude-team-config.git`, затем `claude plugin install comment-guard@bhft-devops`.
- Переключатель — `userConfig.enabled`, по умолчанию **включено**; меняется через `/config`.
- `CLAUDE_COMMENT_GUARD=off` в окружении выключает плагин целиком; читается один раз при загрузке.
- Разработка: `claude --plugin-dir plugins/comment-guard`; headless-прогон без пользовательских хуков: `claude -p --setting-sources project,local --plugin-dir plugins/comment-guard`.
- Если в `~/.claude/settings.json` ещё стоят Python-хуки comment-guard, их нужно убрать, иначе каждая запись судится дважды.

## `/comment-guard-stats [project]`

Таблица по режимам `edit`, `heredoc`, `commit`, `post`, затем строки «main agent», «subagents», топ-5 проектов и «current session». С аргументом — только этот проект. Счётчики лежат в `$.store`, по ключу на сессию, суммируются по всем сессиям плюс архив (сессии старше 30 дней сворачиваются в него при старте). Статистика пишется на диск не чаще раза в минуту и при завершении сессии; `/comment-guard-stats` тоже сохраняет сразу. Hot reload или падение теряет до минуты счётчиков.

| Колонка | Смысл |
|---|---|
| calls | входов в режим, включая post без изменённых файлов |
| checks | вызовов, где что-то реально судилось |
| deny | вызовов с жёсткой находкой (в post — блок через контекст) |
| first / cap | из них первых отказов / отказов без права на повтор |
| resub | повторов, прошедших как ресабмит; `resub%` = resub/first, `!` при > 20 % |
| soft | вызовов с мягкой пометкой |
| fixed | следующая запись в отклонённый файл без отклонённого прогона и с более короткими прогонами |
| open | deny − fixed − resub: не исправлено или переписано в другом месте |
| p50 / p90 | собственное время мода в мс, без времени самой команды |

Строка `cost` — символы/4 всего, что мод вложил в контекст: короткая форма, отказы, post-блоки, пометки, повторно отправленный моделью payload после отказа (`retry`), вывод самой статистики. `savings` — **оценка**: символы предотвращённых строк комментариев / 4, считается один раз. `net` = savings − cost.

## Что не перенесено

Выброшено по решению пользователя или как редкое: проверка MR-описания на Stop, `--find-copies-harder`, сообщение о массовом импорте (молчаливый порог > 20 файлов остался), exec+shebang для файлов без расширения в post, переменные окружения кроме `HOME`/`PWD`, поиск источника копии по каталогу или по одинаковому расширению, глобы в путях, MultiEdit (такого инструмента нет). Отложено: архивация живых сессий старше 30 дней, ключ статистики после `/clear`.

## Известные пробелы

- Вычисленный путь вне репозитория (скрипт сам решает, куда писать) после Bash не проверяется: в команде его не видно.
- Ключ одобрения повтора для ещё не существующего файла строится по пути как он написан; у symlink-родителя повтор не совпадёт с ключом по реальному пути.
- Имя проекта в ключах `$.store` — basename git-корня судимого пути (иначе basename cwd). Два репозитория с одинаковым basename сольются в одну строку.
- `$.store` общий для всех сессий на машине, в том числе headless-прогонов с `--plugin-dir`.
